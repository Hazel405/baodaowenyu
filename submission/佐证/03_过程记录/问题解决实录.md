## 实录 01 · 地名简繁归一失效（2026-10-06）

**发现渠道**：通读检索层代码时发现对照表规模异常。

**问题现象**
`server/rag_server.py` 的简繁转换对照表只有 **19 个汉字**（`兰台莲花东云梦县里斗阿崇庄处乡号湾极与`）。
而库内 31,998 条地名别名使用的汉字达 **2,640 种**——意味着绝大多数简体输入根本无法还原为库内繁体写法。

**定位依据**
1. 逐条统计 `tw.gaz_alias` / `tw.gaz_tw` / `tw.boundary` 全部地名用字 → 2,640 种；
2. 用 OpenCC 正查逐字评估原表覆盖率 → 正确覆盖 **13 字（1.6%）**，漏 **803 字**，另有 **3 字映射错误**（台/里/斗）；
3. `docs/已知限制与改进项.md` 已登记该问题，但未见量化的影响面。

**关键判断：必须用词级转换，不能用单字大表**
实测库内用字分布：`里` 出现 6,380 次、`裡` 仅 63 次 → 库里「里」是**本字**；
若用单字表做简→繁，会把「后里」「万里」这类地名误转为「後裡」「萬裡」。
故采用 OpenCC 的 **`s2tw`（台湾正体）词级**转换，并保留自建表作降级兜底。

**动作**
1. `s2t()` / `t2s()` 改为 OpenCC `s2tw` / `tw2s`，缺失 OpenCC 时自动降级到内置表；
2. 内置扩展表由 19 字扩至 **709 字对**（按 OpenCC 正查 + 库内频次筛选生成，避免歧义选字错误）；
3. `extract_entities` 增加**简繁归一后去重**（见下条踩坑）；
4. 新增 `eval/measure_s2t.py` 作为可复现的量测脚本。

**踩坑与修复（过程留痕，不掩盖）**
- 改动后 QA30 首次回归 **29/30**，第 27 题「台中市和台北谁人口多？」失败。
- 定位：`s2t("台中市")` 现在返回「臺中市」，使简繁变体被当作**两个独立实体**加入 → 实体列表变 `['台中市','臺中市','台北']` → 查询翻倍 → `q_population` 的 `out[:6]` 截断把「台北」挤掉。
- 修复：实体按简繁归一后去重。
- 二次回归成功，但发现第 27 题**数字口径变化**：改进使 `alt IN ('台中市','臺中市')` 额外激活 gaz_tw 的 **ADM2 行政区条目**（2,867,848），跳出测试硬编码区间 → 同步更新期望值并注明口径。

**验证数字（三重）**

| 验证项 | 结果 |
|---|---|
| 名称还原率（31,998 条地名别名） | 30.52% → **84.55%**（+54 个百分点） |
| QA30 回归（30 题基准） | **acc = 1.0（30/30）**，基线未退化 |
| 端到端简体问句实测 | **8/8 命中**（台东/苏澳/芦洲/新庄/员山…） |

**留痕**
- 提交：`12e4f29`（见 `提交历史_含改动明细.txt`）
- 量测脚本：`eval/measure_s2t.py`（可复现）
- 截图：待补 `01_截图/06_问题修复前后/`（简体输入命中繁体库名的前后对比）
- 说明文档：`修改第二版\19_改进A_简繁归一改进说明.md`

## 实录 02 · 数据库转储缺表导致换机必坏（2026-10-04）

**问题现象**
接手包内 `data/db/tw_20261001.dump` 转储只含 71 张 `tw` 表，缺 `tw.pop_county`(22 行) / `tw.pop_town`(204 行) / `tw.cities_major`(20 行) 三张人口表。
而三处代码硬编码依赖这三张表（MVT 瓦片图层、QGIS 插件「览」面板、网页数据导出）→ 换机恢复后三个图层 500、人口层空。

**定位依据**
全项目 grep `CREATE TABLE` 只有一处（`rag_server.py` 建 `tw_demo_townpop`）——证明这三张表**无任何脚本创建**，属原机手工建库遗留。

**动作**：按合规要求重建转储（补齐 3 张表 + 剔除非民用要素表），保持原文件名以兼容 12 处文档引用，在部署说明加版本说明块。

**验证数字**：转储 51,532,142 字节 / SHA256 `ba9a4b59…`（见 `校验值.txt`）；`pg_restore -l` 核出 75 张 TABLE 项。

**留痕**：提交 `8956636`。

## 实录 03 · 评测脚本与制图脚本硬编码旧机路径（2026-10-06）

**问题现象**：`eval/eval_qa30.py` 输出路径写死 `D:\宝岛文舆\eval\outputs`，`scripts/build_demo_project.py` 产物路径写死 `D:\宝岛文舆\`——项目已迁至 `D:\宝岛文娱\宝岛文舆-接手包-20261002`，换机运行会在 D 盘根目录新建计划外目录（已实测复现），且制图脚本换机必失败。

**留痕**：提交 `12e4f29`。

## 实录 04 · 部署文档中的自检命令不存在（2026-10-06）

**问题现象**：`docs/部署说明.md` 与 `接手行动手册.md` 要求执行 `select postgis_libversion();` 自检 PostGIS。

**验证**：实测该函数在 PostGIS 3.x 已移除 → 报 `function does not exist`，队友照抄会卡在自检环节。

**动作**：改为 `SELECT PostGIS_Version();`（已实测可返回 `3.6.0 …`）。

**留痕**：提交 `12e4f29`。
