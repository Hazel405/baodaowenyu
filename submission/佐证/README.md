# 佐证材料目录说明

> 对应《参赛提交材料清单》第 **7** 项「佐证材料」。
> 官方口径（8.1 评审说明）：**佐证材料用于支持相应评分项，不另设泛化附加分**；
> 5.2 明确 **代码行数、材料数量、开发成本不作为评分依据**。
> 因此本目录只放「能支撑评分项的核实证据」，不做材料堆砌。

## 一、目录结构与用途

```
佐证/
├─ 01_截图/                     成果展示与效果验证（大纲五）
│   ├─ 00_运行结果图/            已归档：报告用 6 张生成图（fig_*.png）
│   ├─ 01_插件工作台/            览 / 询 / 较 / 析 四个面板
│   ├─ 02_网页端/                web\ 双模式查看端（MVT 渲染 / 离线快照）
│   ├─ 03_问答与落图/            提问 → 答案 + 来源 + 地图定位高亮
│   ├─ 04_制图出图/              专题图 / 分区统计成品
│   ├─ 05_历史舆图/              历史图叠合、透明度卷帘对比
│   └─ 06_问题修复前后/          ★ 报错截图 → 修好后截图（过程真实性最硬的证据）
├─ 02_评测数据/                 可核验的量化结果（大纲五「验证结果」）
├─ 03_过程记录/                 团队分工、版本迭代、问题解决过程（大纲四）
│   ├─ 提交历史.txt              git 提交一览（15 次）
│   ├─ 提交历史_含改动明细.txt    git log --stat（含每个提交改了哪些文件）
│   ├─ 问题解决实录.md           ★ 逐条记录「发现→定位→方案→验证→数字」
│   └─ AI辅助使用披露.md         ★ 官方强制项：AI 使用环节与人工审核
└─ 04_试用反馈/                 U01–U10 量表原始记录 + 汇总
```

## 二、截图命名规范

`日期_序号_功能_说明.png`，例：

```
1006_01_插件-览面板-图层勾选渲染.png
1006_02_询-三和在哪里-三处同名聚落.png
1006_03_修复前-QGIS浏览面板报错.png
1006_04_修复后-QGIS浏览面板正常.png
1009_05_试用-U03完成T2消歧任务.png
```

要求：1920×1080 或原始分辨率；**画面内不得出现**校名、校徽、教师姓名、成员真名、微信头昵称、无关窗口。

## 三、红线（截图特有）

| 文件名/字段 | 检查动作 |
|---|---|
| Windows 用户名出现在路径栏/终端提示符 | 截图前把窗口拉窄避开路径栏，或截图后裁边 |
| 桌面图标、任务栏、浏览器书签、微信通知 | 录屏/截图前清屏（`Win+D` 后只留目标窗口） |
| 文件属性作者字段 | 交付前清空图片/文档的作者、公司字段 |
| 评测 JSON 内的问答文本 | **见下条** |
| git 提交信息（仅导出副本） | 已统一脱敏为「非民用要素表」；原信息见仓库 commit 列表，处置建议见 `修改第二版\20_留痕与佐证作业单.md` 第六节 |

⚠️ **评测 JSON 的敏感字样**：`eval/outputs/eval_qa30_*.json` 的题面与答案中出现「敏感态势类报道」字样（题集第 21 题）。
**在题集 v2 重跑之前，该文件不得原样打包进 submission。**
处理方式：等队员 B 把第 21 题换成非非民用题、重跑 QA30 后，再将新 JSON 复制到 `02_评测数据/`。
（`disambig300_*.json` 已扫描 0 处敏感词，已归档，可用。）

## 四、与材料清单的对应

| 评分项 | 由本目录哪部分支撑 |
|---|---|
| 实现完成度与可验证效果（25 分） | 01_截图 + 02_评测数据 |
| AI 与开源融合（20 分） | 03_过程记录（AI 使用披露）+ 报告第三章 |
| 创新性（20 分） | 03_过程记录（问题解决实录中的前后对比数字） |
| 附录要求（测试记录、用户反馈、提交记录） | 02 + 03 + 04 |
