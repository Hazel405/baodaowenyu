# 区域模板化平移手册

> 宝岛文舆的区域模板化（Roadmap R2）：把「台湾省人文地理智询」抽象为
> **「任意区域人文地理智询模板」**——一份 `config/region_<code>.json` 配置驱动
> 数据管线、RAG 服务、网页查看端三端。内置 **TW（中国台湾省）**、**FJ（中国福建省）** 两份配置。

## 一、配置契约（`config/region_<code>.json`）

| 键 | 说明 | 示例（TW） |
|---|---|---|
| `name_zh` / `short_zh` | 区域全称 / 短称（服务标题、图层标签用） | 中国台湾省 / 台湾 |
| `pg.dbname` / `pg.schema` | PostgreSQL 库名 / 模式名（同构库平移时二者可相同） | tw / tw |
| `map.center` / `map.zoom` | 网页初始视角 | [121.0, 23.7] / 6.6 |
| `map.bbox` | [minx, miny, maxx, maxy]，数据裁剪与初始 fitBounds 参考 | [119.3, 21.8, 122.1, 25.4] |
| `admin.level1` / `admin.level2` | 两级行政区通名（图层标签：`{level1}人口分级` 等） | 县市 / 乡镇 |
| `timeline.start` / `timeline.end` | 事件快照时间轴口径（YYYY-MM） | 2024-09 / 2026-08 |
| `sources.*` | 数据源登记（geonames / osm / worldpop / gdelt 的参数与复核备注） | 见 region_tw.json |

区域选择优先级：**命令行 `--region` > 环境变量 `BW_REGION` > 默认 `tw`**。
新增配置后先跑静态校验：`C:\bdaopy\python.exe pipeline\region_check.py fj`（缺省校验全部）。

## 二、已接线清单（阶段一，已完成）

| 端 | 文件 | 接线方式 |
|---|---|---|
| 配置加载器 | `pipeline/region.py` | `load()` / `web_subset()`，三端共用 |
| 配置校验器 | `pipeline/region_check.py` | 结构 / bbox / 时间轴 / schema 标识符 / 来源齐备性，7 类校验 |
| 数据管线 | `pipeline/export_web_data.py` | `--region` 参数；SQL 按配置生成（schema 前缀、行政层级标签、事件时间轴），并写出 `web/data/region.json` |
| RAG 服务 | `server/rag_server.py` | `BW_REGION` 读配置；**游标 shim** 把 SQL 内的 `tw.` 前缀重定向到目标 schema（同构库零 SQL 改动）；库名取 `pg.dbname`，标题带区域名 |
| 网页查看端 | `web/app.js` | 启动时 fetch `data/region.json`：中心点/缩放、行政层级标签（人口分级/界线/乡镇）、时间轴月份全部区域化；**文件缺失时整体退回台湾缺省**（旧包向后兼容） |
| 静态服务 | `server/serve_tiles.py` | **零改动**——region.json 是导出时落盘的静态文件，随 web 目录一起被服务 |

TW 回归基线（2026-10-23 复跑）：events **5960** 条（2024-09…2026-08 按月 Top250），
快照总量 1.72 MB，manifest.region = tw。

## 三、十步平移流程（以 FJ 为例）

1. **写配置**：复制 `config/region_fj.json` 改目标区域字段 → `pipeline\region_check.py <code>` 自检 PASS。
2. **建库建模式**：`createdb <dbname>`；库内 `CREATE SCHEMA <schema>; CREATE EXTENSION postgis; CREATE EXTENSION pg_trgm;`。
3. **导数据**：按 `sources.*` 登记的参数跑 `pipeline/import_phase1.py → import_phase3_fast.py → import_boundary.py → load_p0a.py`。
4. **重建瓦片**：`render_tiles.py`（街道）、`make_tiles_terrain.py`（地形，须带 QGIS PROJ 环境，见部署说明 §1.1）、`build_web_tiles.py`（随包低层级）。
5. **导网页快照**：`set BW_REGION=fj && python pipeline\export_web_data.py` → `web/data/*.geojson + region.json`。
6. **起静态服务**：`python server\serve_tiles.py`（零改动；`web/data/region.json` 自动生效）。
7. **起 RAG 服务**：`set BW_REGION=fj && python server\rag_server.py`（shim 自动接管 schema 前缀）。
8. **接 QGIS 插件**：插件内 PG 连接常量指向新库（`plugin/baodao_wenyu/` 内检索 dbname 常量替换）。
9. **复校问答规则**：QA 规则引擎里按区域书写的口径（虚级化、别名还原、行政称谓）需对照新区域复校，并换评测集复跑 `eval/eval_qa30.py`、`eval/eval_disambig300.py`。
10. **更新署名与清单**：页脚/清单按新区域的数据源组合补署名，跑 `scripts\check_redline.py` 后提交。

## 四、阶段二诚实声明（尚未接线，平移时须人工处理）

- **import / render / terrain 脚本的数据源参数仍硬编码**（下载 URL、bbox、GeoNames country、Overpass area id）：
  配置里的 `sources.*` 是"登记 + 复核备注"，import 阶段不会自动读取；步骤 3–4 须人工按登记值改脚本参数。
- **QA 规则引擎的台湾省口径未区域化**：地名虚级化、旧称溯源（`gaz_alias`）、行政称谓规则按台湾数据形态书写，
  平移后须按目标区域地名形态复校（FJ 配置已在 `sources.gdelt.note` 标注关键词域建议）。
- **QGIS 插件面板文案未区域化**：四工作台标题、演示工程名、提示语仍为"宝岛文舆 · 台湾"语境；
  数据链路可平移，展示文案需按目标区域改写（`plugin/baodao_wenyu/i18n` 与面板文件集中修改）。
- **历史舆图模板为台湾专属**：`make_hist_tiles.py` 的清季/日治/1947 时点底图仅覆盖台湾；
  其他区域如需多时点卷帘，须重新制作对应时点的自渲瓦片（红线：仍须全自渲）。

## 五、设计取舍说明

- **为什么 RAG 服务用游标 shim 而不是改 SQL**：950 行问答 SQL 全部手写且经 QA30/DIS300 回归，
  逐条参数化成本高、易引入回归；shim 只在执行前做 `tw.` → `<schema>.` 文本重定向，
  已排查无误伤（OpenCC 配置 `tw2s`、dump 文件名均不含 `tw.` 模式）。
- **为什么 region.json 走静态文件**：serve_tiles 已是"页面 + 瓦片"单端口，region.json 由导出脚本落盘
  即可被同源服务，网页端 no-store 拉取——服务端零新增路由，离线包自带区域信息。
- **为什么网页端允许退回台湾缺省**：旧交付包的 `web/data/` 没有 region.json，
  `loadRegion()` 失败即退回内置台湾视角，保证历史包仍可打开（向后兼容）。

### 6.2 GHSL 人口口径差异（对 TW 的 WorldPop 100m）

- **全省 -7%**：GHSL 全省 38,616,551 vs 七普 41,540,086（-7.0%）。GHSL E2020 为 de facto
  常住人口建模产物，且 1km 分辨率对山区/沿海差异有平滑。
- **厦门低估约 32%**：高人口密度城区在 1km 栅格下被周边山地/水域摊薄最明显。
- 使用约定：FJ 快照人口一律标注 GHSL 口径，不与七普混排；TW 仍用 WorldPop 100m（两口径
  在各自区域自洽，跨区对比须先对齐口径）。

### 6.3 GDELT 事件采样口径（FJ DOC 2.0 vs TW GDELT 1.0 的差异）

TW 用 **GDELT Event Database 1.0**（事件记录：actor/Goldstein/地点编码，双周采样 15,295 条）；
FJ 用 **GDELT DOC 2.0 ArtList API**（文章元数据：标题/URL/seendate/主题），因 Event 1.0 对福建的
中文事件覆盖稀疏。差异须向用户明示：

- **字段**：FJ 无 actor/Goldstein，主题由本地关键词归类（10 类），地点由标题城市关键词 +
  gaz 主名/别名双通道定位，命中落城市、未命中兜底省点（118.1, 26.07）。实测落图率 22.7%。
- **采样窗**：按月 Top250（`maxrecords=250&sort=datedesc`），时间轴 2024-09…2026-08 共 24 窗。
- **GDELT 端行为**：enddatetime 含端日 + datedesc 截断 → 每窗 250 条的 seendate 集中在窗口末日；
  且 enddatetime 会被吸附到日/月边界（如 12-31 23:59:59 等效 01-01），**月中缺口用 ArtList API
  结构性无法填补**（子窗补采的 250 条仍落在边界日）。相邻窗在边界日有少量重叠
  （URL 级去重后仅 3 组重复）。
- **429 节流与缺窗**：GDELT 对客户端 IP 限速严格（实测约半数月份触发 429）。脚本按
  6 次退避（50s+10s×attempt）重试，一轮后 120s 冷却二轮补采。2024-12 两轮均失败、
  定向子窗补采亦被 429 拒绝，该月仅 12-01 有覆盖；2025-12 主窗失败但子窗补采成功
  （文章 seendate 落 2026-01-01，在时间轴内有效）；2024-09 窗的文章 seendate 落在 2024-10-01。
  快照导出按时间轴过滤，超界行不入包。
- 落图兜底与缺窗属采样口径限制，演示与问答中均按"示例事件"呈现，不作为事件全量统计依据。

### 6.4 行政口径备注

- boundary 84 个县级建制为 DataV 现行口径，**不含金门**（金门属泉州市辖但由台湾实际管辖，
  FJ 模板按大陆现行统计口径处理，与 TW 区域的金门标注各自成区，不混用）。
- GeoNames CN 主名为罗马字（如 Fuzhou），中文名全在 gaz_alias——地名匹配必须双通道，
  已在 import_fj.py 的 locate() 落实。
