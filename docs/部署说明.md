# 部署说明 · 宝岛文舆

> 面向二次开发与复现验证：照本文在一台干净的 Windows 机器上，**从零跑到能演示**。
> 作品主体是 QGIS 插件；网页查看端与 RAG 服务是它的配套。

## 0. 系统构成（先建立整体感）

| 组件 | 位置 | 端口 | 作用 |
|---|---|---|---|
| PostgreSQL + PostGIS | 外部安装 | 5433（本项目实例） | 唯一数据底座。`tw` 模式 **73 张表**（`information_schema.tables` 口径，含分区）；其中 **23 张独立业务表 ≈49.5 万条**；对外知识库口径为 **20 表 ≈48 万条**（482,916 条，与技术报告一致） |
| RAG 服务 | `server/rag_server.py` | 8600 | 问答 `/api/ask`、实体定位 `/api/locate`、图层元数据 `/api/layers`、矢量瓦片 `/mvt/...` |
| 静态服务 | `server/serve_tiles.py` | 8090 | 自产 XYZ 瓦片金字塔 **+ 网页查看端页面**（同一端口） |
| Ollama | 外部安装 | 11434 | 本地跑 `qwen3:8b`，只负责"把检索结果组织成话" |
| QGIS 插件 | `plugin/baodao_wenyu/` | — | 作品主体：览/询/较/析 四工作台 |
| 网页查看端 | `web/` | 8090 | 双模式：实时（MVT+问答）/ 离线（随包快照） |

数据流：开放数据 → `pipeline/` 脚本 → PostGIS → （QGIS 插件 / MVT / 自渲瓦片）→ 界面。
**所有数字都来自 SQL 检索，大模型不参与取数**——改任何回答逻辑都要守住这条。

### 两条图层链路（不要误读为"数据不一致"）

网页静态快照与服务端 MVT 是**两条独立链路，图层清单不必一一对应**：

| | 服务端 MVT 实时瓦片 | 网页静态快照 |
|---|---|---|
| 入口 | `server/rag_server.py` 的 `/mvt/...` | `web/data/*.geojson`（随包离线） |
| 图层来源 | `MVT_LAYERS` **白名单**（14 层） | `pipeline/export_web_data.py` 只列**民用要素表**（9 层） |
| 运行方式 | 需 PG + RAG 服务在线 | 随包离线，`?offline=1` 强制降级 |

图层数差异是**刻意收敛**（白名单只放行可对外展示图层，静态快照进一步只取民用要素），不是数据缺失。
**两者字段口径以各自文档为准；任一方字段名改动都必须通知对方**，避免联调时误判。

### 1.1 跑 `pipeline/` 脚本必须带 QGIS 的 PROJ/GDAL 环境（实测踩坑，必读）

直接调用 `QGIS\apps\Python312\python.exe` 跑 `pipeline\make_tiles_terrain.py` 会失败：

```
RuntimeError: Cannot parse CRS http://www.opengis.net/def/crs/EPSG/0/2193
  May be caused by: PROJ: proj_create: no database context specified
```

原因：直连该解释器时 `PROJ_LIB` / `GDAL_DATA` 未设置，GDAL 找不到 `proj.db`。

**两种正确跑法（任选其一）：**

```bat
:: 方式 1（推荐）：用仓库自带包装脚本，自动设好环境并 cd 到项目根
scripts\run_with_qgis_py.bat pipeline\make_tiles_terrain.py

:: 方式 2：手工设环境变量
set "QGIS=C:\Program Files\QGIS 3.44.15"
set "PROJ_LIB=%QGIS%\share\proj"
set "GDAL_DATA=%QGIS%\apps\gdal\share\gdal"
set "PATH=%QGIS%\bin;%QGIS%\apps\gdal\bin;%QGIS%\apps\Python312;%PATH%"
"%QGIS%\apps\Python312\python.exe" pipeline\make_tiles_terrain.py
```

> 注意："不要用系统 Python 跑管线脚本"这条约定依然成立；本节说的是"用 QGIS 自带 Python 时还要额外带 PROJ 环境"。

## 5. 演示与开发入口

```bat
scripts\start_web_demo.bat        :: 起两个服务并打开 http://127.0.0.1:8090/
```

- **网页端实时模式**：徽标显示"实时"，图层走 `/mvt`，问答走 `/api/ask`，答案实体自动落图。
- **网页端离线模式**：只跑 `serve_tiles.py`，或访问 `http://127.0.0.1:8090/?offline=1` 强制降级（降级不必停服务）。
- **在线对照底图**（实时/离线均可）：底图下拉框一键切 Esri 卫星影像 / Esri 街道图 / **OSM 标准图**——仅浏览器在线引用，不落盘、不缓存、不随包分发，署名内置页脚；网络不可达自动禁用 Esri 项并回落自产底图。地图右上角悬浮面板可快捷切换三个在线底图 + 太空→街道俯冲演示。
- **镜头直达（视频录制/快速演示）**：URL 加 `?shot=<name>` 在加载完成后自动摆好状态，内置 `dive`（俯冲）/ `osm` `esristreet`（同视角分屏对照素材）/ `satellite` `street` `terrain`（全域各底图）/ `events`（事件时间轴自动播放）/ `qa`（自动提问演示）。
- **QGIS 侧**：点工具栏 **★ 打开演示工程** → 载入 `demo_project.qgz`（人口分级设色 + 晕渲底图 + 中文注记 + 事件点）。
  该工程由 `python scripts\build_demo_project.py` 生成，改样式改这个脚本。
- 图层工作台是"勾选即增删"的实时模式；加载矢量层时插件会做 4326↔3857 坐标变换后再定位（缺这步会白屏）。

## 8. 常见故障对照

| 症状 | 原因 | 处置 |
|---|---|---|
| 插件不出现/工具栏没有 | 未写 `QGIS3.ini` 的 `[PythonPlugins]`（注册表无效） | 见 4.2 |
| 点图层后画布全白 | XYZ 底图把工程 CRS 拉成 3857，矢量 extent 按 4326 算 | 已修：加载后 `setCrs(4326)` + 缩放前坐标变换；自建图层时照做 |
| 打开演示工程报 Python 错误 | 用了 `QgsProject.read(QFileInfo)` | 用 `QgsProject.instance().clear()` + `iface.openProject(path)` |
| 问答很慢/超时 | Ollama 冷启动或半截 pull 把 daemon 锁死 | 杀掉 `ollama app.exe` 与 `ollama.exe` 全部进程树后 `ollama serve`；服务已配 `keep_alive=30m` + 启动预热 |
| `ollama serve` 起后 `/api/generate` 500，且 `%USERPROFILE%\.ollama\models\manifests-v2*` 报 Access is denied（ACL/属性都正常） | 本机安全软件拦截命令行方式启动的 ollama 对 `.ollama` 目录的写入 | 改用托盘程序启动：开始菜单运行 `Ollama`（`ollama app.exe`），任务栏出现羊驼图标即就绪；比赛演示机优先用托盘方式 |
| 终端里中文变乱码 / JSON 报错 | Windows 默认 GBK 控制台 | 用 `python -c "import urllib.request..."` 或文件传参，别用 curl 发中文 |
| `.bat` 闪退 | bat 里写了中文注释/路径 | bat 保持纯 ASCII，用 `%~dp0` 定位 |
| 批量拷贝中文目录后文件数不对 | robocopy 在 git-bash 下 GBK 路径误报成功 | 用 Python `shutil.copytree` 并**拷贝后校验文件计数** |
| 改了 `web/app.js` 页面没变化 | 静态服务把 html/js 也长缓存了 | 已改：`.png/.pbf` 长缓存，其余 `no-store`；仍异常就 Ctrl+F5 |
| MVT 500 | 图层白名单里 SQL 字段名写错 | 看返回体里的 PG 错误串；`/api/layers` 可核对字段 |
| 网页渲染不出（自动化测试里） | 页面处于 hidden 状态时 `requestAnimationFrame` 不跑 | 用正常可见浏览器 |
| 跑 `pipeline/` 脚本报 `PROJ: proj_create: no database context specified` | 直连 `apps\Python312\python.exe` 时未设 `PROJ_LIB`/`GDAL_DATA` | 见 §1.1：用 `scripts\run_with_qgis_py.bat` 或手工设环境变量 |
| 脚本报 `FileNotFoundError`（绝对路径） | 个别管线脚本 `ROOT` 仍是硬编码盘符 | 把项目放在任意不含中文的路径，或把该常量改为按 `__file__` 自动定位（多数脚本已是此写法，可参照） |

## 9. 合规要求（请勿改动）

- 材料、截图、文件名、仓库内容**一律不得出现**非民用要素、敏感字样、校名/校徽/指导教师姓名（匿名评审）。
- 底图红线 = **零第三方瓦片再分发**：随包 `basemap/` 全部由本项目管线自渲；另允许网页端**客户端在线引用**带署名的公共底图端点（Esri World Imagery / World Street Map，见《开源及第三方资源使用清单》#20）——仅实时拉取显示，禁止导出、缓存、预下载或随包分发第三方瓦片；端点不可达时自动回落自产瓦片。
- 对外接口按 `server/rag_server.py` 的 `MVT_LAYERS` **图层白名单**放行；离线快照由 `pipeline/export_web_data.py` 只列民用要素表。新增图层必须显式加白名单，不要开放任意 SQL/任意表名。
- 涉台地图表达按《地图管理条例》自查：台湾省为中国省级行政区域，金门、马祖作相应标注；网页端**随包离线交付，不做公网托管**。
- 不提交任何密钥/口令与本地配置（`config_local.py`、`*.key`、`*.env` 已在 .gitignore）；推远端前建议扫一遍历史文件：
  ```bat
  git log --all --name-only --pretty=format: | sort -u | findstr /i "internal export raw derived msi probe"
  ```
  有输出就说明不该提交的文件进了历史，需清除后再推。
- Git 提交建议使用团队匿名身份，**不要改全局 git config**：
  `git -c user.name="BaodaoWenyu Team" -c user.email="baodao.wenyu.team@example.com" commit -m "..."`
- **保存 QGIS 工程后先跑红线自检**：QGIS 保存 `demo_project.qgz` 时会把**本机系统用户名**写进 `saveUser` 属性；若曾临时筛选过图层，筛选条件也会被一并保存（曾出现只剩一个县）。两者都不应随交付物外泄：
  ```bat
  python scripts\check_redline.py            :: 自检工程 + 全仓文本（身份线索 / 敏感字样）；FAIL 就别提交
  python scripts\check_redline.py --fix      :: 自动净化：saveUser 改中性、boundary 复位 level=2
  git restore demo_project.qgz               :: 或直接回滚到仓库版本（最稳）
  ```
  仓库已附 pre-commit 钩子（`scripts\install_hooks.bat` 一键安装）：提交含"脏" `demo_project.qgz` 时自动拦截。
